# 人口生命周期与步行 AI

## 0.4.4：视线、记忆与警员情报

步行追逐现在结合 `WorldPerception` 的有效视线和最后已知位置。NPC 自身确认 60 米内无遮挡视线后，才可在 40 米内进入战斗；每 500 毫秒可刷新查询，确认最多有效 1,000 毫秒。查询未知、超时、缺少 `physics_queries` 观察者或旧结果失效时不授予射击权限。双方代次、所有权和超过 0.75 米的坐标漂移均参与有效性检查。

视线丢失后，目的地保持为最后目击坐标，不再随不可见目标实时移动；记忆最长 10 秒，抵达 1.5 米内等待。自卫与警方也可追踪服务端已接受攻击时记录的历史声源位置。同一警力响应的活动警员通过两遍汇总共享目击位置，任务结果不依赖实体遍历顺序；情报仅支持追踪，每名警员仍需自身视线授权才可开火。

这些任务沿用下文的步行导航、卡住恢复及模拟权移交。原有局部覆盖边界不变；不包含掩体选择、完整视野角度或战术队形。`/health` 与 `/world` 的 `ai_perception` 报告实际感知状态。兼容现有 0.2.16 客户端桥，无需修改玩家资源或重新构建启动器。详见 [NPC 感知](npc-perception.md#简体中文)。0.4.4 发布和美国线路更新由既有工作流执行，实际运行状态以部署报告为准。

## 步行导航

`extract_ped_navigation.py` 从当前受支持引擎对应的 YNV 资源只读提取导航面、普通邻接边和高度。出生区 600×600 米范围读取 25 个 YNV：41,216 个原始多边形被安全三角化为 92,681 个导航单元、228,074 条有向连接。

`PedNavigation` 使用三维最近点、A* 和共享边通道生成路线，避免将高架与地面混为一层，也不将两个多边形中心直接跨墙相连。非凸面先进行耳切分割；载入时再次验证邻接确实共享同一条几何边。跳跃、攀爬、动态导航和未支持的特殊连接不用于本轮路径。

`WorldAi` 为漫游、逃跑和徒步追逐下发路线的下一段目标。客户端只执行到点移动，不自行决定新的漫游目标。目标不跳过转角通道；短路点变化也更新任务版本，避免三米更新阈值吞掉短路径。

连续三秒没有确认进展时，服务器重新选路。漫游更换可达目标；逃跑或追逐尝试封禁原路线第一个通道后的替代路线。没有安全旁路时暂时等待并重试，不传送、不穿墙。位置明显偏离路线也会触发重新规划。客户端定期续发尚未完成的三秒原生任务，避免等待新世界版本才重新行走。

当前导航文件是局部覆盖。安装了导航但当前位置无可行路线时，任务明确进入 `walk_navigation_unavailable`；未安装导航的旧兼容模式仍保留原来的受限原生行为。不能将局部路径测试描述为全地图一比一 NPC 行为。

## 死亡、废弃和人口补充

服务器为每个活动格记录独立行人/交通槽位；生命结果仍以 Registry 为准。

| 情况 | 服务器规则 |
| --- | --- |
| 死亡 NPC | 至少保留 30 秒；所有活跃玩家在 40 米外后可清理；最长保留 120 秒 |
| 无活司机或损坏的环境车辆 | 至少保留 60 秒，远离玩家后清理；最长 180 秒 |
| 车辆已删除后的孤立司机 | 保留宽限期后清理，避免永久占住交通槽位 |
| 空槽位 | 确认旧实体消失后等待 15 秒，且附近有活跃玩家、实际出生点不在玩家 20 米内，才补充 |
| 玩家占用/已接管车辆 | 不由人口清理删除，也不会通过整格退役删除 |

补充创建使用新的世界 ID，旧尸体墓碑不会重新出现。交通车辆与司机同时计入容量预算；没有足够空间不会只生成半组。一次维护的生命周期创建/删除总实体成本最多四个，初次活动格填充及整个远区退休仍沿用独立流程。

客户端死亡 NPC 固定在服务器确认位置、停止任务且不自行复活。删除通过已有墓碑/快照流传播，所有端卸载同一实体。现阶段尚未加入完整尸体布娃娃物理复制或救护复苏。

## 模拟权移交

所有权选择使用 NPC/车辆的实际确认位置，不再只看出生格。现模拟者仍有效且距实体不超过 400 米时保留；需要新模拟者时从 300 米内的存活、有效租约玩家中选择，避免每帧追逐最近玩家而抖动。

车辆与附座 NPC 属于同一组，以一个 Registry 事务转移归属；新模拟者仍需完成 `entity_ready`。旧 epoch 的输入不能继续控制，新客户端驾驶前同时检查车辆和司机都已激活。玩家驾驶位始终优先，人口模块不能把其控制权转交给旁观者。

## 数据安装与验证

```sh
python3 -B tools/extract_ped_navigation.py
python3 -B tools/build_multiplayer_server.py
java -jar server/multiplayer-server.jar --world-data server/world-data
```

新增的 `server/world-data/ped-navigation.bin` 和审计元数据需随服务器独立数据目录安装，不提交游戏派生几何。`/health`、`/world` 的 `pedestrian_navigation` 和 `population` 提供实际加载数量、重规划/卡住恢复/清理/补充计数。

验证覆盖：真实 YNV 提取和路径、恶意/损坏数据、三维楼层区别、不同通道绕行、卡住重试、死亡/新代际、30/120 秒清理、15 秒补充、玩家车辆保护、容量不足、重复维护、车与司机原子移交及旧 owner 拒绝。

本轮导航、人口、所有权、碰撞、道路、武器、资源输出保护等 94 项核心回归，以及真实 JAR 协议、战斗、车辆、近战、环境和连接超时等 103 项回归全部通过。真实导航抽样 40 条漫游和 40 条返程路线通过。加载实际世界数据的最新八人 30 秒协议持续测试处理 4,608 次玩家状态、291 次实体批次，39,324 次增量接收无错误和序号缺口。导航恢复计数来自静止协议模拟者，不能据此宣称真实 NPC 已完成避障行走。

公网主线路与实验线路均通过 Node 24 默认可信证书验证的 HTTPS 健康检查与 WSS 加入、完整世界快照和心跳验证，没有跳过 TLS 证书检查。`/health` 确认版本为 `0.4.2-world-experimental`，两条线路均加载 92,681 个步行导航单元、228,074 条有向连接、301,339 个静态碰撞三角形与 77,824 个道路节点。部署前后本轮使用的原始引擎、清单及两个导航源 RPF 的 SHA-256 均保持不变；未修改游戏目录。

回滚备份位于服务器 `/opt/gta5data-server/backups/20261009T100852Z-before-0.4.2`；每条线路的 JAR 与六个独立世界数据文件均在 staging 和安装后验证 SHA-256。当前步行与静态碰撞仍只覆盖出生区约 600×600 米；`game_sync: false`、`coverage_complete: false` 继续如实报告这些边界。
