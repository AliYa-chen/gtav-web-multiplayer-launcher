# 武器目录与权威战斗

服务端目前从本地 `gta5data/data/common/data/ai/weapons.meta` 固定生成武器目录，不再只认识原先的 22 个枪械 hash。`tools/generate_weapon_catalog.py --check` 校验当前资源与生成的 `WeaponCatalog.java` 完全一致，生成文件同时保存资源 SHA-256。Java 服务器运行时无需游戏资源目录。

本地文件有 91 个 `CWeaponInfo`。这些记录同时包括手持武器、动物攻击、载具武器、工具，以及落水、火灾、被车辆碾压等伤害原因。服务端另保留之前已经公开的 SNS Pistol、Compact Rifle、Marksman Rifle 三项兼容规则，以及旧桥接层加载角色时使用的 `weapon=0` 空手别名，共 95 项。不能把 95 个目录项都当成玩家可开枪的武器。

| 服务端类型 | 数量 | 处理方式 |
| --- | ---: | --- |
| `hitscan` | 24 | 按有限射线寻找最近存活角色，服务端统一扣血。 |
| `shotgun` | 4 | 资源中的 8 枚弹丸和 `BatchSpread` 产生确定性散射，分别寻找最近目标后汇总一次伤害事务。 |
| `projectile` | 20 | 创建服务端投射物，延迟飞行、命中/到达终点/到期、爆炸或工具效果。 |
| `melee` | 23 | 由近战交互处理，包含空手加载别名及动物攻击目录项。 |
| `utility` | 6 | 灭火器、汽油桶、扫描仪、夜视、降落伞、提箱等明确归为工具，不捏造子弹伤害。 |
| `environment` | 18 | 跌落、落水、撞击等伤害原因，不接受伪装成手持武器的射击请求。 |

## 资源事实和服务器规则

原始文件明确提供 `FireType`、`DamageType`、`Damage`、`TimeBetweenShots`、`BulletsInBatch`、`BatchSpread`、`WeaponRange`，以及弹药的 `LaunchSpeed`、`GravityFactor`、`LifeTime`、`ExplosionTime`。客户端 `welcome.weapon_rules` 同时公开模式、伤害、节奏、范围、散射、飞行参数、近战规则和原始 `asset_damage`，避免把兼容值伪称为原游戏参数。

已发布的 22 个普通枪械保留原服务端伤害和射击节奏。原来每次扣 50 血的霰弹枪现在把这 50 点分配给 8 枚弹丸：近距离全部命中仍是 50 点，远处可能只有部分弹丸命中，也可分散命中多名角色。确定性散射只由已接受的序号与目录参数决定，客户端不能提交每枚弹丸的目标或伤害。

本地近战记录的 `Damage` 是零；实际原生近战还依赖动作与任务系统。因此空手 20、刀 45、其他近战/枪托 35、两米判定距离是明确的服务器玩法规则，不是从零字段推导出的原游戏伤害。服务器爆炸 150 点/六米线性衰减、火焰 20 点/四米、BZ 气体 10 点/五米同样属于玩法规则。`explosion.ymt` 是 PSIN 二进制，本轮没有将其解析为完整原生爆炸参数。

## 高频输入和事件生命周期

客户端采集同时观察本次射击脉冲、弹匣和总弹药变化。已确认扣弹的连续射击不再在桥接层按服务器冷却被直接丢弃；一次回调之间发生多发扣弹时保留有界数量的射击意图。射击脉冲先出现、扣弹稍后到达时按逐发待确认计数去重；换弹阶段的计数变化不会作为开火。引擎桥与网络桥各最多保留八个待发意图，网络层只施加 10 毫秒发送间隔，实际伤害和武器节奏仍由服务器裁决。背压超过一秒、换枪、死亡或断线会清理待发输入。

射线改为当前相机方向与服务器公布的武器射程，不再使用没有射击时间戳的 `GET_PED_LAST_WEAPON_IMPACT_COORD` 覆盖瞄准。该 native 可能仍返回上一发、上一把武器或上一目标的落点，因此会让后续有效射击沿旧方向判定。目录中的长枪不再被客户端固定的 100 米射线提前截断；这不扩大已加载地图或原生碰撞查询的覆盖范围，当前原生观察者仍只接受自身 180 米内的几何查询，超出时不会假定无遮挡。

正常快速 `shot_event` 不再因为尚未到射击时间就返回 `rate_limited`。服务器先验证当前生命、武器、位置、输入形状和递增序号；已经到时间立即执行，否则返回 `shot_queued`，带 `pending=true` 和 `scheduled_at`。每名玩家最多保存八个待执行意图；超出时以最新意图替换队尾，并发布被替换序号的 `shot_cancelled(reason=coalesced)`，不会因高频操作弹错误，也不会让任意报文频率变成即时无限伤害。

队列到期按武器节奏执行，瞄准方向保留，枪口随最新确认的角色位置平移。更换武器、断线、死亡、生命周期换代或位置状态过期会清除旧意图，旧角色的排队射击不能在重生后继续发射。非法坐标、伪造武器、重复序号等输入仍然拒绝。

投射物执行后发布 `projectile_event`，阶段为 `launch`、`landed`、`expired`；`projectile_state` 提供晚加入时仍活动的投射物与区域效果。爆炸发布独立 `explosion_event`，然后由同一权威伤害事务向所有相关角色扣血。爆炸包括射手自身，且同一爆炸的多个击杀累计一次事务；原射手已经换代时，不将旧投射物的击杀计入新生命。

手雷按资源中的四秒寿命引爆；黏弹保留到拥有者提交 `detonate` 意图，其他玩家不能指定其爆点或代为引爆。燃烧瓶与 BZ 气体产生八秒区域效果，每秒一次，重复服务端 tick 不重复叠加同一时间的伤害。每人最多 16 个活动投射物/区域效果，全局最多 128 个，且远程黏弹有两分钟生命周期。

## 仍需独立完成的原生能力

0.4.1 已接入真实 YBN 静态三角形、材质属性、道路图和原生碰撞查询协议。新客户端使用 `server_trajectories_world_queries`：服务端按速度和重力推进运动段，结合静态几何和受分配引擎的异步碰撞候选决定遮挡、落点和反弹；不再把瞄准终点当作确定落点。完整实现、数据安装、验证结果与剩余边界见 [服务端碰撞与物理实现](服务端碰撞与物理实现.md)。没有安装地图或不支持查询的兼容模式仍有限制，健康接口显示实际能力。移动载具黏附、任意厚度穿透、全量原生接触物理、火势传播及完整电击动作仍未完成。

仅安装服务端静态地图、客户端没有原生查询能力时，无遮挡的轨迹段也须继续飞行并检查角色胶囊。已修复把这类查询的空票据误判为投射物过期的问题；真正失败或超时的异步查询仍终止投射物，不将未知几何当成已验证的命中。

工具射击已被分类并同步，但汽油桶铺油、灭火器消火、夜视等工具的完整玩法状态仍需单独迁移。目录的存在也不等于完成了服务器背包、弹药消耗、武器拾取或载具武器挂载权限；这些应采用独立的权威物品/装备事务，不能靠客户端声明的 `weapon` 当作最终库存证明。

客户端应仅把 `projectile_event` 和 `explosion_event` 用于无伤害表现，避免远端原生子弹/爆炸再次产生本地生命变化。

## 验证

维护者本地武器目录回归使用实际 Java 世界与确定性时钟，验证完整目录、所有可射击项接受、每种有伤害投射物最终扣血、双方互伤、霰弹近远命中、武器范围、延迟爆炸、自伤、手雷计时、黏弹权限、燃烧周期、效果容量、高频队列和断线/死亡/换武器取消。

维护者本地战斗协议回归使用真实 WebSocket 和编译 JAR，继续验证生命不可由客户端改写、最近目标、普通枪兼容伤害、目录广播、排队射击、协议伪造拒绝及身份恢复。相关回归文件不随源码分发。以上记录覆盖资源、服务器与协议。

本轮补充的本地回归实际通过：99 项 Java 武器目录/有伤害项/静态地图投射物断言，22 项原生采集 mock 断言，以及 7 项真实 WebSocket 连发、短时背压、队列容量、过期和换枪断言；另以两项注入已确认死亡消息的检查验证待发队列清理。Mock 用来复现输入时序与旧命中坐标问题，不等同于双客户端游戏画面验收。车辆的子弹/爆炸伤害和车型碰撞体仍未接入同一权威伤害事务；目录中的载具武器也尚无挂载权限与背包证明。
