# 公共战局的天气和时间

天气和时钟由轻量 Java 服务端唯一生成。客户端只接收并调用游戏原生接口应用，不根据本机时区或单人脚本自行推进公共世界。实现参考公共战局的环境同步职责划分，没有复制 FiveM 或其它项目的源代码。

## 协议

服务端能力列表新增 `world_environment`。`snapshot_begin`、`snapshot_end`、`world_delta`、`/world` 和 `/health`（也可访问 `/api/multiplayer`）均附完整 `environment`。环境不参加 300/400 米实体范围过滤。快照开始和结束包含相同 cut；连接连续序号仍由 `stream_seq` 统一维护。

```json
{
  "world_epoch": "当前世界身份",
  "world_tick": 1800000000000,
  "environment": {
    "revision": 1,
    "weather": {
      "type": "EXTRASUNNY",
      "rain": 0,
      "wind": 0.2,
      "transition_ms": 0,
      "anchor_tick": 1800000000000
    },
    "clock": {
      "hour": 12,
      "minute": 0,
      "second": 0,
      "paused": false,
      "rate": 30,
      "anchor_tick": 1800000000000
    }
  }
}
```

- `world_tick` 和 `anchor_tick` 是服务端单调毫秒。服务端以启动时 UTC 毫秒作为起点，用单调时钟推进，不随操作系统校时跳变。
- 环境 `revision` 独立于实体 `world_revision`；每五秒更新 checkpoint，即使没有玩家移动也发送完整环境增量。所有客户端在同一 checkpoint 读取相同值。
- `clock.rate` 单位是游戏秒/真实秒，默认 30，等价于两秒推进一个游戏分钟。世界从 12:00 开始；到午夜按 24 小时回绕。
- 天气由服务端固定预报循环产生，每十五分钟进入下一段；过渡默认三十秒，首次进入没有过渡。`rain` 和 `wind` 是目标强度（0–1）。天气过渡起点使用 `weather.anchor_tick`，晚加入客户端根据已经过去的时间应用，避免各自从零开始不同步。

客户端记录收到新环境修订时的 `world_tick` 和本机 `performance.now()`。当前估算服务端时间为接收的 `world_tick + 本机经过毫秒`，然后由 `clock.anchor_tick` 推进锚定的时、分、秒。重收同修订不得重新锚定；实体增量可以继续推进实体状态，不应把旧环境锚点的本机接收时刻反复延后。

发现 `stream_seq` 缺口时请求 `world_sync`，在完整快照结束后一次应用实体、环境和其它全局事实。世界 epoch 改变时必须清空旧环境。环境跳过 checkpoint 可接受，因为每次都带完整值；旧环境修订不能覆盖新环境。

客户端没有修改天气、时间、暂停或速度的命令。伪造的 `environment_state` 为未知消息；把环境塞入实体或玩家输入同样被字段白名单拒绝。环境数据的输入来源只可能是服务端代码。

## 当前校验范围

维护者本地 Java 环境夹具涵盖 checkpoint 幂等、30 倍换算、午夜回绕、天气周期、不可变基线与旧 tick 拒绝。对应的本地协议回归涵盖双端/恢复快照、闲置纠时、连续流、客户端写环境拒绝，以及缺少环境/执法能力拒绝与超过十六项的完整能力声明。

相关验证文件不随源码分发。用户允许构建后，已使用隔离临时 JAR 验证环境 Java 夹具、六项真实环境协议回归、十三项统一世界协议回归、十二项共享车辆回归和两项人口退役回归。测试不运行游戏资源；页面、原生画面和八人持续联机验收仍由用户进行。

这层统一天气和时间，并不意味着 Java 独立计算 GTA 的全部 AI 和物理。共享 NPC、车辆与警察需要唯一实体、模拟者租约和事件裁决；它们由世界注册表和执法规则层负责，不能仅靠统一环境达到完整 GTA Online 行为。
