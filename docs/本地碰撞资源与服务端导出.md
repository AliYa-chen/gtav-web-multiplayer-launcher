# 本地碰撞资源与服务端导出

本次实际解开了本地 RPF 目录并读取 YBN 几何。原先“没有独立 `.ybn` 文件”的扫描结果不能用于判断地图没有碰撞：资源就在归档里。服务器现在可以直接加载由本机资源生成的世界坐标三角形；完整原生物理仍需继续处理下面列出的边界。

## 本地证据

1,528 个 RPF 的目录使用 `0x0ffffff9` AES 标识。本工具从匹配版本的 `game.wasm` 被动数据段和 `__wasm_init_memory` 指令重建初始化数据，定位本地 AES 构造器实际引用的材料，并用 RPF 根目录结构与真实 `.ynd` 文件名验证解码。密钥留在处理进程内，不写入源码、报告或导出文件。没有下载解包软件或外部游戏资源。

本次读取归档目录得到：

| 资源 | 实际条目数 | 作用 |
| --- | ---: | --- |
| `.ybn` | 15,557 | 静态碰撞 bounds；其中 GTA5 关卡路径包含 8,707 个 |
| `.ymap` | 5,853 | 世界实体与模型放置，后续用于补足内嵌碰撞 |
| `.ytyp` | 977 | 模型类型与原型属性 |
| `.ynd` | 383 | 路径网络 |
| `.ynv` | 4,404 | 行人导航网格 |
| `.ydr` / `.yft` | 66,295 / 6,054 | 绘制模型、碎片/载具模型；可能含内嵌碰撞 |

这是归档条目数量，可能包含同名、变体、LOD 和不同关卡，不能当成互不重复的世界对象数量。发现的 261 个嵌套 RPF 尚未递归解包。此前直接扫描物理目录得到的“无独立 YBN/YND/YNV”与本次发现并不冲突。

当前快照的主要 YBN 内容使用 16 字节快照前缀和 Zstandard 帧；解压后包含原生 RAGE 系统资源指针。`_prologue` 下另有 147 个 YBN 使用尚未处理的内容编码，错误清单保留在导出元数据里。它们未被假定为洛圣都出生区域的空地。

## 几何格式由本地函数确认

导出器没有把模型包围盒当成墙。它解析复合 bound 的子对象和变换矩阵，并解码真实的三角形顶点：

| 本地 WASM 函数 | 已确认内容 |
| --- | --- |
| `67028 phBoundPolyhedron::GetVertex` | 顶点指针偏移 176，计数 208；每顶点 3 个有符号 `int16`；按偏移 144 的逐轴缩放和偏移 160 的中心恢复坐标 |
| `16489 phBoundComposite::DeclareStruct` | 复合 bound 的子对象和变换布局 |
| `16547 phBoundGeometry::GetPolygonMaterialIndex` | 多边形数偏移 212，逐多边形材质索引指针偏移 280 |
| `16546 phBoundGeometry::GetMaterialId` | 材质表指针偏移 240，每条 8 字节 |
| `16545 phBoundGeometry::GetNumMaterials` | 材质条数位于偏移 288 |
| `43185 phMaterialMgrGta::Load` | 明确设置材质索引掩码 `255`；导出低 8 位原生材质编号 |

原生材质编号与 shape-test 返回的材质名称 hash 不是同一种字段，服务端应显式转换，不能直接比较这两个整数。

### 材质与原生返回 hash

`common/data/materials/materials.dat` 为 12.00 版，共 213 个材质。当前加载器的 `sscanf` 格式为 6 个字符串、10 个浮点数和 6 个整数，与文件实际列相符：摩擦 6、弹性 7、穿透阻力 15、`SEE_THRU` 16、`SHOOT_THRU` 17、`SHOOT_THRU_FX` 18、`NO_DECAL` 19、`POROUS` 20、`HEATS_TYRE` 21。末尾第 22 列为附加材质标签，不能替换第 0 列的原生名称。文件的历史注释提及燃烧属性，但当前 12.00 数据列没有这些值，因此未从注释编造燃烧参数。

`59410 CommandGetShapeTestResultIncludingMaterial` 只取命中材质低 8 位，把这个编号传给 `15752 phMaterialMgr::GetMaterialName`。后者实际返回 `名称_编号`，再由 `2740 atStringHash` 做 Jenkins hash。**直接对 `CONCRETE` 做 hash 得不到原生返回值**：正确形式是 `CONCRETE_1`，结果为 `1187676648`；`TARMAC_4` 为 `282940568`。这一点已落实到 `MaterialCatalog.byCode`，它同时接受索引、实际原生 hash 和明确的无后缀名称 hash 兼容别名。

213 个材质中有 18 个标记为 `SHOOT_THRU`，例如编号 112 的 `GLASS_SHOOT_THROUGH`。`SEE_THRU` 与 `SHOOT_THRU` 是独立标志：篷布允许武器 probe 通过但阻挡 AI 视觉。不能用“透明材质”一条规则同时决定射击与 AI 感知。

## 本机实际导出

运行：

```sh
python3 -B tools/export_world_collision.py --evidence-output docs/snapshot/collision-resource-evidence.json
```

默认范围是出生点 `(711, -1088, 22)` 周围：`[411, -1388, -100]` 到 `[1011, -788, 300]`。可通过 `--bounds minX minY minZ maxX maxY maxZ` 更改。默认扫描 GTA5 关卡的所有 YBN，再保留与指定范围相交的真实三角形；`--path-prefix` 仅用于明确缩小归档范围。

此次导出涉及 134 个 YBN 资源，得到 **301,339 个去重三角形**，文件大小 **12,053,620 字节**。从 `(711,-1088,200)` 垂直向下查找真实三角形，得到地面高度 `21.4132`（材质 4）和 `21.4096`（材质 0）；与本地出生高度 22 相符。这验证了坐标恢复和导出内容，并不替代实际游戏内的物理测试。

产物为 `server/world-data/collision.bin` 和 `collision.meta.json`。几何属于玩家本地游戏数据，不应放入源码分发包。报告保留源归档路径、资源名、压缩与解压内容 SHA-256、范围、条数和所有未支持项；不含解密密钥。

二进制格式均为大端：

| 字段 | 格式 |
| --- | --- |
| 标识 | 8 字节 ASCII `GTACOL1\n` |
| 请求范围 | 6 个 `float64`：min XYZ、max XYZ |
| 三角形数 | `int32` |
| 每个三角形 | 9 个 `float32` 世界坐标 + 1 个 `int32` 原生材质编号；每条 40 字节 |

范围表示本次选择区域，**不是该区域的碰撞完整性证明**。元数据始终标识 `coverage_complete=false` 和 `static_ybn_triangles_only`。服务器不能将范围内未命中导出三角形直接等价于本地引擎确认无遮挡。

## 尚需实现的精确边界

- 默认区域还有 72,900 个嵌入 box primitive、5,033 个 capsule primitive、287 个 sphere primitive 和 747 个 cylinder primitive 尚未导出。工具明确计数并略过；不以它们的 AABB 伪装精确碰撞。
- 保留了与区域相交的各个 YBN 变体，但没有重现 `hi@` / `ma@` / 基础 bound 的流式激活和 LOD 选择。服务端应把它称为保守静态三角形模型，不能声称与每帧本地碰撞世界完全一致。
- 尚未将复合 bound 的 type/include 筛选、材质的高位多边形标志和原生 shape-test 掩码映射到服务端。透明、可射穿和特殊表面需要这些语义，不能仅靠几何三角形判定完整的穿透行为。
- YDR/YFT 内嵌碰撞、YMAP 放置、门与载具的移动变换、破坏状态没有包含在静态导出中。服务器公共世界还应维护这些对象的权威状态，并按当前变换参与查询。
- YNV 已被定位到真实归档，但本导出器没有把导航多边形当成碰撞面，也没有据此宣称行人寻路已完成。

10 项独立结构测试覆盖坐标缩放、复合变换、越界指针、无效顶点与材质、循环子对象、非有限数以及未知 primitive 计数。真实资源检查另验证了导出文件长度和上述出生区域交点。尚未据此宣称双客户端视觉、原生动态碰撞、反弹、穿透或火势蔓延测试通过。

材质目录另外通过 5 项资源/格式测试及 Java 17 运行检查，核对 213 个索引、原生 hash 与无后缀别名、射穿标志和未知值处理。可用 `python3 -B tools/generate_material_catalog.py --check` 校验生成源码是否仍与本地资源一致。
