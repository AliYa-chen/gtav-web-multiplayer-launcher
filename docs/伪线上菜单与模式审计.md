# 自有在线战局的菜单与模式审计

日期：2026-10-08。只读检查原始 `game.wasm`（SHA256 `11ca8d2c04c5e843d18ff4aea4899d72c86973c6b031df334e67c446b2ae83e0`）、已有启动代码及项目 UI XML；31 个目标函数完整解码。对照公开 NativeDB/CitizenFX 资料，缓存仅保存到系统 `/tmp`。**原 WASM 与 `gta5data/data` 没有修改；本轮实现了独立启动器桥和受控 native 测试，游戏画面验证仍由用户完成。**

`client/multiplayer/native-session-ui.js` 已实现 `self.createNativeSessionUI({ex,memory})`，返回 `tick(now,summary)`、`reset()`、`dispose()`。它要求显式 `summary.online === true`，并在原生暂停菜单和 frontend 均就绪时显示公共战局标题、昵称、人数、连接状态与自由模式详情。连接状态支持 `connecting/loading/active/reconnecting/leaving`，关闭战局停止覆盖；昵称剥离游戏格式、HTML 特殊字符、控制字符，使用独立 1280 字节受限 UTF-8 缓冲。正常每 750ms 有限重应用，状态变化最短间隔 250ms，菜单重开立即更新。原 network flag、查询结果及菜单版本均未改动。

`node --test tools/tests/test_native_session_ui.cjs` 的 6 项测试通过，覆盖显式在线标记与资源守卫、参数 ABI、状态更新/重开、UTF-8 边界、Begin/参数失败恢复、内存增长与释放。另以真实桥的受控调用验证没有脚本 owner 时，独立前端 marker 仍刷新菜单且不调用任何实体命令。受控替身测试不能证明运行时布局或实际游戏体验；原生菜单显示仍属于实验能力。

## 暂停调度与 frontend 专用接入点

静态核对已确认：原单机沙盒暂停菜单打开后，不能依赖实体同步使用的 `scrThread::Run` owner 回调。`CPauseMenu::Open`（36164）在文件偏移 21565572 调用 `fwTimer::StartUserPause(1)`（8918），后者把 user-pause byte `12321460` 与 pause-full-update byte `6632112` 置为 1。`CTheScripts::Process`（63788）在 33043393 汇总暂停状态；33043418 的 `br_if 1` 直接跳到外层 block 的末尾 33067781，跳过真正的脚本调度（33065391 按 thread 虚表 `+32` 调用 `(i64,i32)→i32` 的 Update）。所以 `main_persistent` 在这条路径没有 Run hook，单靠 owner tick 的菜单更新会停止。

当前公共运行副本已单独插入 frontend 回调：`CPauseMenu::Update`（36291，`()→void`）由 `CGameSessionStateMachine::Update` 在 18000247 调用，条件是暂停菜单 active。原函数正常结束点 21716304（指令起点 21691809，相对偏移 24495）位于原方法全部 End 完成后的栈恢复前；此处没有 `scrThread`/handler 身份需要构造。正常尾部原字节为 `20064280047c24000b`，原完整 body `[21691800,21716313)` 的 SHA256 为 `77649c56f6a2303de1a31efd373ae4757fde6a95bf6e77d3cf33f8f1e6df3c63`。构建器核对完整 body 哈希与尾部，再沿用既有 JS 导入发送独立 frontend marker；补丁回归另外核对完整解码与指令位置。回调参数 `0` 只是无语义 payload，绝非真实游戏对象指针；回调仅允许共享状态读取和受守卫的菜单 API，不得调用角色/车辆/所有权接口或实体 owner 逻辑。

`mpBeginPauseHeader`（50805）只有诊断日志分支会调用 `CTheScripts::GetCurrentScriptName`（63799）。后者在 script-processing flag `23496104` 为 0 时返回固定字串，不读取 TLS；原调度在 33065109 置 1，并在 33065580 清 0。其下的 `BeginMethod`（37248/36044）、`AddParamString`（36056）、`AddParamBool`（36051）与 `EndMethod`（36050/36045）没有脚本线程或 handler 依赖，沿用当前 frontend 阶段的 Scaleform 上下文。这里证明的是正常尾部接入与 API 依赖边界；实际菜单布局和线上体验仍须游戏验证。

## 可以显示自有在线身份，但不能只改查询就进入原线上模式

项目的 Java 公共战局已经有自己的连接、玩家和统一世界状态。可以让游戏内原生菜单显示“公共在線戰局”、昵称、人数、连接状态和游戏模式；这属于自有在线体验的 UI 适配。缺少原网络管理器时，把真实 GTA Online flag、session state 或菜单版本直接改为多人值，会使原代码进入另一套会话、好友、云统计、钱包和网络对象路径。

本轮已经选择：**保留真实沙盒 world、C++ 网络状态和所有原脚本查询返回值，只用已有 frontend Scaleform 的 header 方法覆盖菜单标题/详情，为自有菜单提供自己的状态来源。** 下文查询 wrapper 仅列作静态边界证据，没有实施伪返回值或激活原线上脚本。

## 原 native 查询和包装器

下表索引是原 WASM 函数索引，偏移为原文件零起字节位置。NativeDB 的 hash 是原脚本 native 标识，不能作为 WASM 函数索引。

| 查询 | C++ 实现索引 / 偏移 / 长度 | 脚本包装器索引 / 偏移 / 长度 | 实际 ABI |
| --- | --- | --- | --- |
| `NETWORK_IS_GAME_IN_PROGRESS` | 54706 / 31661306 / 105 | 55538 / 31788211 / 113 | 实现 `()→i32`；wrapper `(i64)→void` |
| `NETWORK_IS_SESSION_ACTIVE` | 54707 / 31661412 / 6 | 55539 / 31788325 / 20 | 同上 |
| `NETWORK_IS_SESSION_STARTED` | 54708 / 31661419 / 6 | 55540 / 31788346 / 20 | 同上 |
| `NETWORK_GET_GAME_MODE` | 54711 / 31661440 / 26 | 55545 / 31788475 / 35 | 同上，游戏模式为整数 |

54706 与其 wrapper 中都内联读取线性内存 `28501281` 的 byte，另有日志缓存状态更新。它不是调用 Java 状态，也没有构造 session。54707 转到 82912 `NetworkInterface::IsInSession()`；54708 转到 83019 `IsSessionEstablished()`。两个实现读取全局 session 指针 `29044456`，指针为空时返回 false；不为空时读取 session `+99916`：active 比较 `!=0`，started 比较 `==5`。

54711 和 55545 在 `IsInSession()` 成功后取 `NetworkInterface::GetMatchConfig()`（83074），再调用 `NetworkGameConfig::GetGameMode()`（85727）；未入会话返回 -1。**不能先把 active 查询改成 true，再允许原 game-mode 代码对空 match config 解引用。** 自有覆盖需要完整地返回自有模式结果，原实现仍保留给原引擎。

四个 wrapper 最终从 `scrThread::Info` 参数 `+0` 读取结果缓冲区 i64，再在结果缓冲区 `+0` 写 int32。这是修改原脚本查询结果的明确隔离边界。例如 55539 原完整体：

```text
01 01 7f 10 e0 87 05 21 01 20 00 29 03 00 20 01 36 02 00 0b
```

表示调用 82912、保存 bool、取 Info 结果指针、写 i32。55538 的 flag 查询是内联，不能只改变 54706 期待 wrapper 跟着改变。

从二进制结构看，wrapper 的返回缓冲区是可定位的隔离边界；但本轮不修改它。自己的游戏正在恢复身份、资源尚未就绪时不能宣布 started，短时断线也不应把当前玩家立即切回故事世界。自有状态通过独立 bridge/API 提供，来源于 Java 会话和已应用快照，而不是 URL 中一个 `online=1`。

但原脚本往往会在得到 true 后继续查询 host/player/net ID/云数据或注册网络脚本。当前 `NETWORK_SET_THIS_SCRIPT_IS_NETWORK_SCRIPT`（54840）和 TRY 入口 54841 都可能更换 handler。因此，只改四个返回值仍可能引发缺失网络对象的后续调用。优先用于自有新增 UI/脚本的查询兼容，或者先观测调用脚本名单与后续依赖；**不要把它当作激活原 freemode 控制器的开关。**

## 浏览器启动模式没有“Online”枚举证据

现有 `WasmInputBlock.startMode` 位于输入块 `+440`：1 故事、2 GTA V 沙盒、3 env_test 沙盒，公共 `/play/` 当前固定 mode=sandbox。原函数 `ArgStartMode()`（567）实际 ABI `()→i32`，解析 `-DoReleaseStartup` 为 1、`-sandbox` 为 2，并识别 `-wasmstartchoice=` 的数值写入选择变量。相应静态字符串文件偏移为 49543098、48627423、51576085。

本次没有找到 browser start mode 中一个可安全使用的原线上值。`startMode=2` 是地图/启动流程选择，不等于 `NETWORK_GET_GAME_MODE` 的多人玩法枚举；不能把 2 或新造的 4 同时塞给两者。模式字段应分别表达“底层 GTA V 沙盒 world”与“自有公共战局玩法”，后者可通过新 bridge/API 显示为在线。

## 暂停菜单直接走原 C++ 状态

`CPauseMenu::OpenCorrectMenu(bool)`（36288，21690930 / 363 字节）直接读取 `28501281`，多人分支用菜单 hash `-1171018317`；其它分支选择故事/创建者布局。它没有调用前述脚本 wrapper。因此，wrapper 伪 online 不会自动让 Esc 菜单变成多人。

原 `pausemenu.XML` 的多人版本确实存在：

- `FE_MENU_VERSION_MP_PAUSE` 以 `MENU_UNIQUE_ID_HEADER_MULTIPLAYER` 为首屏，标题 label 为 `FE_THDR_GTAO`，初始 context 为 `InMP`。
- 故事版本是 `FE_MENU_VERSION_SP_PAUSE`、`MENU_UNIQUE_ID_HEADER`、`PM_PAUSE_HDR`、`InSP`。
- MP header 含地图、任务创建器、朋友、信息、统计、设置、画廊等；某些商城链接及 MP 共享组件也在同资源中。
- SP“游戏”页 `MENU_UNIQUE_ID_GAME` 使用 `PAUSE_MENU_SP_Repeat` 脚本，含重玩任务、载入/新游戏、退出等。修改页签文案并不会把该页的动作变成自有公共战局操作。

`CPauseMenu::Open(...)`（36164，21562870 / 5232 字节）包含 ROS credentials、好友刷新、clan delegate、统计请求、暂停流程和 XML 结构装配。`UpdatePlayerInfoAtTopOfScreen`（36296，21720818 / 2536 字节）读取真实网络 flag，并使用 `IsInFreeMode()`、多人钱包/银行、云统计/角色卡等分支。菜单真实调用关系说明：直接 `ACTIVATE_FRONTEND_MENU(MP hash,...)` 或激活 `InMP` context，不是单纯换皮。

`PAUSE_MENU_ACTIVATE_CONTEXT`（51845）/DEACTIVATE（51846）ABI `(i32 hash)→void`，转到 SUI context 系统，可过滤某些 UI 项；本次不建议伪造 `InMP` 来解锁整个原 MP 页面。`SET_PAUSE_MENU_ACTIVE`（51835）只写另一个 pause 控制 byte，也不改变战局模式。

## 原生 header 显示有明确、安全边界较小的入口

NativeDB 明确把下列 API 描述为自定义 frontend 内容/header 的入口。本 WASM 也保留了具体方法：

| API / 实现名称 | 索引 | 实际 WASM ABI | 守卫与用途 |
| --- | ---: | --- | --- |
| `CommandIsPauseMenuActive` | 51840 | `()→i32` | 原 pause active 查询。 |
| `CommandIsFrontendReadyForControl` | 51856 | `()→i32` | 先检查 pause active，再检查 frontend movie active。 |
| `CommandBeginScaleformMovieMethodOnFrontendHeader` | 50805 | `(i64 method)→i32` | 先检查 pause active、header movie handle `>=0`；成功才 BeginMethod。 |
| `CommandBeginScaleformMovieMethodOnFrontend` | 50804 | `(i64 method)→i32` | 同样检查 active 与 content handle，适合内容方法。 |
| `CommandScaleformMovieMethodAddParamInt` | 50812 | `(i32)→void` | 给已经成功 Begin 的同次调用增加参数。 |
| `CommandScaleformMovieMethodAddParamBool` | 50814 | `(i32)→void` | 同上。 |
| `CommandScaleformMovieMethodAddParamLiteralString` | 50818 | `(i64 text)→void` | 转到 AddParamString；接受 UTF-8 NUL 字符串指针。 |
| `CommandEndScaleformMovieMethod` | 50806 | `()→void` | 完成方法调用。 |

Begin 返回 false 时不能继续 Add/End。同一 tick 连续调用，字符串保留到 End 返回；单独分配受限缓冲，过滤 `~` 格式指令、控制字符和用户输入。只对当前公共战局页生效，原单机菜单保持原体。结束战局需要停止刷新覆盖；短断线可以显示恢复连接而不切换原菜单版本。

原代码已经使用的具体 header 方法：

- `SET_HEADER_TITLE`：`CPauseMenu::Update` 的静态方法字串位于文件 51407341，实际调用指令位于 21710884 / 21713071；不是猜测 Scaleform 方法名字。已重新完整解码调用：21710884 的正常分支只发送一个字符串，再 End；另一个重建分支传四个 `Param`。第一实现采用原正常分支的单字符串形式，不猜测其它参数；运行时标题布局仍须实测。
- `SET_HEADING_DETAILS`：原 36296 在 21723141 引用；调用按顺序送三项字符串、一个 bool、最后一项字符串。可以显示昵称、公共战局人数、服务器/连接状态，但四行含义与布局须实测。
- `SET_MENU_HEADER_TEXT_BY_INDEX`：36277 `SetupHeaderTextAndHighlights` 在 21681626 引用，原参数为 index、label、0、0。可研究改某个页签显示文本；**更名不修改该页原动作**，不能把“游戏”页写成在线后保留载入存档按钮欺骗用户。

不建议直接使用 `CPauseMenu::SetCurrentMissionLabel`（36395）传任意昵称来换标题：它通过 formatf 把输入作为格式串写入 64 字节缓存，含 `%` 的名字存在额外契约问题，而且此字段不是菜单版本/标题的独立原生 API。现有 literal-string Scaleform 参数更直接。

没有找到该 WASM 中一个等价于 FiveM `ADD_TEXT_ENTRY`、可直接把任意 label 文案覆盖为字符串的普通原 native。`CTextFile::Get` 77479/77481 与额外文本资源加载接口存在，但资源级添加不是前端 label runtime 覆盖接口。禁止编辑原 GXT、UI XML 或 data 目录时，优先用 literal-string 参数及独立自有内容，而非修改游戏字库/文本包。

## 推荐交付顺序

1. **菜单明确在线身份。** Esc 菜单正常加载后，通过 guard 检查 header ready，标题显示“公共在線戰局”，详情显示自有昵称、在线人数和连接状态；消息来自同页 Java 连接。保留现有地图/设置页面，先不打开原朋友、银行、商城或新游戏流程。
2. **定义自有游戏模式契约。** 自有 API 使用 `public_freeroam`，状态区分连接中、快照就绪、游玩、重连；内部 map=GTA V，browser start 保持2。原查询和 NetworkGameConfig 保持原行为，自有 UI 读取独立 bridge，不伪造它们已初始化。
3. **交互菜单完整实现。** 自有玩家列表、断线状态、返回主页等按钮走自有协议；原页签若换文案，必须连同交互控制一起接管。对于仍未支持的原线上功能，不能只把入口标题改成 Online。
4. **原菜单每次重建后有限重应用。** CPauseMenu 的 Update 会重建 header，不宜每个游戏帧抢写。记录 pause 打开/布局变化状态，以低频/状态变化重应用；退出和资源未就绪时静默回退，不把 Begin 失败升级为引擎同步崩溃。
5. **验收独立。** 双客户端在线加入、Esc 开闭、地图/设置、断线恢复、退出重进，确认标题及模式正确且无后台原认证/云依赖错误。编译和静态检查只证明接口可定位，不证明该 UI 运行可靠。

## NativeDB / CitizenFX 对照与区别

对照 [alloc8or NativeDB JSON](https://github.com/alloc8or/gta5-nativedb-data/blob/master/natives.json) 与 [CitizenFX natives](https://github.com/citizenfx/natives)：

| NativeDB API | hash |
| --- | --- |
| NETWORK_IS_GAME_IN_PROGRESS | `0x10FAB35428CCC9D7` |
| NETWORK_IS_SESSION_ACTIVE | `0xD83C2B94E7508980` |
| NETWORK_IS_SESSION_STARTED | `0x9DE624D2FC4B603F` |
| NETWORK_GET_GAME_MODE | `0x4C9034162368E206` |
| BEGIN_SCALEFORM_MOVIE_METHOD_ON_FRONTEND_HEADER | `0xB9449845F73F5E9C` |
| BEGIN_SCALEFORM_MOVIE_METHOD_ON_FRONTEND | `0xAB58C27C2E6123C6` |
| SCALEFORM_MOVIE_METHOD_ADD_PARAM_LITERAL_STRING | `0x77FE3402004CD1B0` |
| ACTIVATE_FRONTEND_MENU | `0xEF01D36B9C9D0C7B` |

NativeDB 的描述支持通过 frontend/header API 定制文字，但它是 PC GTA native 资料；本项目应以自己 type 节和守卫为准。例如该构建 `SET_PAUSE_MENU_ACTIVE` ABI只有一个 bool，网络身份/API契约也没有对应 Java 环境。

[FiveM NetHook.cpp](https://github.com/citizenfx/fivem/blob/master/code/components/gta-net-five/src/NetHook.cpp) 的实代码在 join/host 流程中构造 peer/gamerHandle/地址和 session key，调用原 joinGame/hostGame，等待 `g_isNetGame` 与 `isSessionStarted()` 成功，才设置自己的 `networkInited`。它不是仅把四个脚本返回值改成 true。当前浏览器移植没有这些已验证的 peer/session 初始化条件，不能直接搬用其 PC patch 地址或结构偏移。

[FiveM PatchPauseMenuBuilds.cpp](https://github.com/citizenfx/fivem/blob/master/code/components/gta-core-five/src/PatchPauseMenuBuilds.cpp) 在原菜单 context 激活后附加 build context。它说明 menu context 是独立 UI 适配层，不证明修改 InMP 就完成网络初始化。其数据包还提供专门 pausemenu.xml；用户要求不改 data 时，本项目不能照搬那种资源覆盖。

详细只读证据另存在 ignored `docs/snapshot/pseudo-online-menu-evidence.json`。公共资料仅缓存于 `/tmp/gta5-nativedb-pseudo-online.json`、`/tmp/gta5-fivem-NetHook.cpp`、`/tmp/gta5-fivem-PatchPauseMenuBuilds.cpp` 及对应 native Markdown。原 `gta5data/data` 只有读取，没有写入。
