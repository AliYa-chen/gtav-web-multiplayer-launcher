# 服务器世界规则迁移

当前采用轻量 Java 共同世界：服务器发布唯一实体目录、时间、天气、通缉、任务意图及生命周期；被授权的客户端运行 GTA 引擎的 AI、物理、资源加载和表现。客户端未持有租约的区域不能再生成另一套可交互人口。

这与把原单机脚本直接放进 Java 运行不同。原脚本依赖 GTA 的 native、任务系统、场景、路径、碰撞、流式加载和引擎对象，现有 RPF 内脚本也未提取成可直接运行的源码。Java 服务端没有这些引擎设施。需要逐项把“世界实例和重要结果的决定权”迁到服务器，并保留经过授权的客户端引擎模拟。也不能将 GTA Online 描述成所有 AI 和物理都在一台服务器执行：其具体网络架构与本项目当前实现不同。

## 世界规则与执行端

| 规则 | 服务端负责 | 客户端负责 |
| --- | --- | --- |
| 时间、天气 | 世界环境版本、时钟锚点、速率、天气切换 | 根据同一锚点推进显示，应用引擎环境参数 |
| 人口、交通 | 稳定实体 ID、区域预算、任务意图、创建/删除与唯一租约 | 当前租约持有者运行原 AI/物理；其余端应用确认的副本 |
| 犯罪、警力 | 根据已经接受的行为/伤害更新通缉，决定响应组及目标 | 显示服务器通缉；租约持有者执行警员/车辆任务 |
| 伤害、死亡 | 验证来源、代次、序号和明显范围异常；提交生命事务 | 报告输入或获授权的模拟候选，应用已确认生命状态 |
| 被捕、重部署 | 确认共同警员、距离、通缉和代次；批准四秒等待与重生 | 抑制独立医院/警局重启，按确认事务恢复镜头和控制 |
| 所有权交接 | 提供基线、等待资源就绪、授予带 epoch 的租约 | 资源与碰撞就绪后确认；失去租约立即停止主动模拟 |

关闭单机剧情脚本需要保留资源加载、HUD、输入和世界基础系统。不能把全部脚本线程清空，也不能仅伪造官方会话标志；这会进入尚未初始化的官方网络/账号流程。在线模式应采用明确的共同世界策略：限制本地人口和独立警察调度，约束单机生命周期，并只允许服务器计划产生共同事件。

## 犯罪与共享警力规则模块

[WorldLaw.java](../server/src/main/java/offline/multiplayer/WorldLaw.java) 不拥有 `WorldRegistry`，不直接创建实体或写入生命值。它保存通缉计时、调度组关联和规则版本，产生供 `WorldService` 提交的决定。

- `reportAcceptedShot` 仅接收已由战斗规则接受的枪械动作；校验玩家活动租约、当前武器与起点六米范围，每五秒至多记录一次射击犯罪。
- `reportAcceptedDamage` 只在伤害已经原子提交后接收实际伤害，普通攻击至少两星、击杀三星；攻击已登记的响应警员至少三星、击杀四星。视觉弹道和旧血量观测不能单独增加伤害或通缉。
- 通缉由服务端时间推进：一至两星在四十五秒没有新犯罪后开始逐级降低，较高通缉先等待九十秒；后续每三十秒降一星。尚未实现完整视野、掩体和搜索区模拟，因此不声称复现官方逃脱规则。
- `reportArrestCandidate` 只接受当前玩家代次、服务端已有通缉、低速步行状态和三米内的本次响应警员。警员须属于真实共享实体、存活、有活动租约并已有至少一次确认的模拟输入；局部引擎自行宣布被捕不能直接将玩家设为死亡。
- `clearAfterRedeploy` 只在服务器已增加玩家代次后清空通缉；旧代次报告不能清除新角色的状态。

`snapshot` 带独立 `revision`、世界 epoch、所有玩家的通缉和响应组信息。连接应在完整快照和世界增量中传送它，并在仅通缉计时变化时也发送更新，避免没有实体运动就不发布世界规则。断线恢复须重新取得当前规则版本。

## 共享响应组的提交

`tick` 接收当前登记实体、允许模拟世界的玩家集合与实际剩余容量，返回 `DispatchDecision`：

1. `spawn`：一辆警车、两名警员，顺序固定为车辆/警员/警员。`WorldService` 必须把两个警员分别挂接到驾驶位与乘客位，再绑定真实实体 ID；不能在同一坐标留两个独立碰撞角色。
2. 调用 `dispatchCommitted` 绑定创建结果，沿现有基线、资源就绪、租约激活链分配模拟。创建失败需回滚已创建的实体并调用 `dispatchFailed`；尚未绑定的邀请五秒超时，之后允许重试。
3. `pursue`：更新追踪目标、代次和建议模拟者。服务器授予租约才是模拟权限，`ResponseInfo.ownerId` 只是选择结果，不能跳过 Registry 的所有者 epoch。
4. `freeze`：没有合适模拟者、目标断线或超出当前实验区域时，保留实体及最后确认状态，停止本地主动追击。玩家恢复后可以重新提供基线和激活租约。
5. `retire`：通缉消失、目标死亡/重生或离开世界后，服务端删除响应警员及未占用的车辆，再移除规则关联。如果玩家已经通过座位事务取得警车，保留该共享车辆与座位、清除警力任务标记，不能为了撤警让玩家车消失。客户端不能独立将警员交回单机人口系统。

`responseForEntity` 返回响应 ID、角色、目标玩家/实体/代次、目标位置、建议模拟者和阶段。将这些字段并入共享实体的任务描述，可让所有客户端知道同一批警员正在追踪同一角色。独立 `task_revision` 允许在姿态版本没有改变时更新追踪目标和任务阶段，客户端只合并新任务元数据，不回滚同版本生命与姿态。车辆、驾驶员和乘客需作为一组订阅与迁移；玩家驾驶座事务始终优先于调度建议的模拟者。

首阶段响应数量上限为八组、共二十四个实体；现有人口最多一百九十二个实体、八位玩家和公共车辆，仍在二百五十六个登记实体预算内。实际可用容量不足时，模块等待，不删除其他共同实体以强行生成警力。

## 目前刻意保留的实验范围

响应生成仅限公共出生区附近二百二十米，从既有公共车辆基线派生固定停车排布（七米列距、四米排距），并排除与已登记车辆、步行角色及待提交响应的明显重叠。服务器没有已经验证的全地图警车落地点、寻路或碰撞图，因此不会把玩家任意三维坐标当成可靠道路坐标。客户端仍须在引擎中确认模型、地面/碰撞与座位资源就绪后才激活模拟。几何间距检查不包含静态地图碰撞查询。

轻量服务端可以检查警员射击报告者是否持有活动租约、目标代次是否当前、射击冷却和确认位置是否合理，并统一扣血与广播。它没有完整地图碰撞数据时，不能独立重算墙体遮挡或 GTA 弹道。人口性格、场景事件、交通路线及更完整警察搜索仍需要扩展服务器任务计划和经授权的原引擎适配。

服务端规则通过临时 Java harness 检查权限、代次、调度与事务。

## 本轮落地与验证范围

新增环境和执法层已接入同一 world_v2 连续流，环境/执法各有独立版本，警察目标有 `task_revision`。
暂停菜单及不同 Worker 的时间原点通过同一绝对单调时间基准转换，避免玩家暂停或刷新后出现各自时钟。
合法原生天气过渡只触发一次，结束后恢复持久天气；本地随机警察、dispatch 和目击报案被抑制。
AI 枪械/近战原生伤害倍率设为零，服务器仅接受活动警员租约的射击候选，按确认位置、目标代次和冷却统一扣血。
轻量服务端没有地图 LOS 或完整 AI 仿真；警员射击候选仍有模拟者可信边界，不能描述为独立重算每发 GTA 弹道。

本轮测试涵盖环境快照/晚加入/闲置纠时、旧消息拒绝、服务器犯罪/共享警力、抢警车租约和退休保留乘客、原生 ABI 与客户端模拟路径。
公共出生区之外的警力派遣、地面/碰撞资源就绪和警员任务动画仍是实验能力。
