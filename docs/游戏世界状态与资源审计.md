审计日期：2026-10-08。对象是当前项目实际保存的 GTA V 数据，以及原始 `gta5data/b/8b0b5899ed/game.wasm`。本次只做文件目录、资源头、XML/文本和 WASM 指令静态解析，没有启动游戏引擎、调用游戏 native、修改游戏数据或部署服务端。

## 结论与研发边界

当前数据与引擎包含环境行人、交通、场景活动、警察调度、角色死亡/逮捕重启，以及原网络实体和同步树。共同世界所需的素材和部分运行逻辑并未缺失。当前多人实现缺少的是统一的世界实例、实体生命周期、模拟所有权和引擎模式约束；增加几个动作或伤害消息不能消除各客户端各自运行单机世界的冲突。

有一个实际存在的载入车辆遍历命令，也有通用空间查询入口；没有发现可直接导出的通用 `GET_GAME_POOL` 或完整行人池枚举 API。已有车辆遍历会创建脚本 GUID，空间查询需要真实的搜索体和 WASM 回调，二者都不能当成浏览器任意线程里的纯只读函数。

更合适的整体方向是先规定“一个公共世界中哪些对象由谁生成、谁模拟、谁有权改变生命周期”，再建立统一实体采样和应用层。Java 服务端可裁决对象身份、所有权、生命、重生、座位、任务意图和事件顺序；原 GTA AI/物理继续在受授权的引擎实例中执行。若要求服务端独立计算完整 GTA AI、车辆物理、导航与碰撞，则需要无渲染引擎或另行重建模拟，不能让现有只保存 JSON 的 Java 程序凭空获得这些能力。

### 4.2 车辆数组 ABI 有具体证据

61943 的 236 字节函数体已完整解码，原体文件范围为 `[函数体起点, 结束)`，实际调用的关键步骤为：

1. 从版本固定地址 `26005240` 取得车辆池管理结构；随后读容量、元素步长和占用位数组。
2. 从调用方 `buffer + 0` 读取 **i32 最大输出容量**。
3. 输出指针从 `buffer + 8` 开始，每个结果存 **i32 GUID**，然后指针增加 **8 字节**。
4. 每个选中实体调用 `rage::fwScriptGuid::CreateGuid` / 8689；返回实际填入数量。
5. 存在基于实体扩展与 `entity + 216` 标志的过滤：掩码 `983040`，比较值 `458752`。本次没有把这两个数强行解释成未经核对的业务枚举名称。

因此，缓冲区应按 `(capacity + 1) × 8` 字节规划，不能按普通连续 i32 数组只分配 `(capacity + 1) × 4`。读取结果时使用 `8 + index × 8` 的偏移。固定地址只是本版本静态结构线索；不能跳过 WASM 哈希、初始化、占用位和实际对象校验直接在任意页面帧使用。

8689 的函数体为 291 字节，调用 `fwExtensionList::Get`、`fwBasePool::New` 和 `fwExtensionList::Add`。这意味着把现有实体变成脚本 GUID 可能分配资源/添加扩展，**遍历结果接口并非纯只读**。它不等同于为服务器注册所有权；GUID 分配与脚本实体登记是两条机制。

`gameconfig.xml` 有 `Any` 与 `pc` 配置覆盖。基础值为 `Peds=110`、`Vehicles=148`、`Object=1000`；`pc` 覆盖为 `Peds=256`、`Vehicles=276`、`Object=1600`，另有 `Dummy Object=20000`。这些是资源配置上限，不是在线玩家上限，也不能证明运行时一定选用了某组容量。

### 4.3 更稳妥的统一采样层

应建立一个有版本校验、执行阶段校验、容量上限和代际校验的实体枚举包装层。它可以利用原世界空间索引采样相关区域，或读取经审计的 ped/vehicle/object 池；将结果复制成不可变的小快照，再交给页内网络会话。不要把整段可变 WASM 内存作为世界快照发送。

统一对象记录至少区分：服务器稳定 `entity_id`、本地 GUID/池槽位、generation、类型、模型、位置/旋转/速度、population 类型、生命阶段、所有者与 lease epoch、车辆/座位/附着关系、外观与任务意图。对象删除需要 tombstone；池槽位被复用后必须增加 generation，不能把新对象当成旧玩家或旧车继续更新。

对于浏览器桥，搜索回调需要真实 WASM 函数或新增的专用包装器。当前桥没有 `addFunction`/通用 C 回调构造能力；传普通 JavaScript 函数或假搜索结构地址，会破坏 ABI。直接池读取也需要在生成、删除和异步任务不会同时修改集合的阶段执行，不能仅凭当前脚本 handler 有效就推断整个世界池不会并发变化。

“本地 script handler 持有实体”“服务端允许某用户控制实体”“原 netObject 所有者”是三个不同层次。现有创建角色/车辆 native 的网络参数可以为 false，走局部实体路径；这能生成视觉副本，但不自动建立原网络管理器与控制权迁移。

共同世界需要固定的持久脚本归属或经审计的资源所有权包装层。随意选择当前出现的短命任务脚本，可能使副本在脚本退出时被原清理链删掉。创建、接纳现存环境对象、转移所有权和释放对象应成为统一事务；每次写入前核对实体仍存在、generation 与 lease epoch 有效。

车辆还需要统一座位与乘员关系。已经定位读取/应用入口：`CommandGetVehiclePedIsIn` / 57184、`CommandGetPedInVehicleSeat` / 61366、`CommandSetPedIntoVehicle` / 57201、`CommandTaskEnterVehicle` / 60571、`CommandTaskLeaveVehicle` / 60572、`CommandTaskWarpPedIntoVehicle` / 60716。它们是对象操作工具，不提供“两人同时抢驾驶位”的服务端裁决，也不会替当前 JSON 协议管理车辆控制权。

## 6. 警察、死亡和逮捕需要统一模式状态机

不能把“NPC 死亡”“玩家死了”“玩家医院重启”“服务端允许重生”“原角色对象已经换代”视为一个布尔值。它们在原引擎中有不同入口和副作用。

`CGameLogic::Update()` / 18879 有 7,277 字节完整函数体，涉及玩家状态、传送完成、音乐、统计、UI 和移植层 `wasm_start_mode_now`。`CRestart` 的医院、警局、安全屋、覆盖重启分别存在实际接口：医院 19174、警局 19176、覆盖 19181、取消 19182。

`CommandPauseDeathArrestRestart(bool)` / 52750 的 12 字节函数体只把布尔值写入地址 `15493005` 的一个字节。它是一个模式开关，并非阻止全部原脚本、相机、角色替换与玩家状态变化的完整隔离层。`CommandSetFadeOutAfterDeath` / 52752、`CommandSetFadeOutAfterArrest` / 52753、`CommandSetFadeInAfterDeathArrest` / 52754 又是独立命令。

`CGameLogic::ResurrectLocalPlayer(...)` / 18883 有 3,321 字节，直接调用包括：

- 原网络玩家重生检查/角色重建、`CPed::Resurrect` / 46186 与摄像机重置。
- 移除警用直升机、清理拾取物、车库操作、清理 UI/暂停状态。
- 清理火灾归因、惊吓事件、爆炸/投射物犯罪归因、事故与调度 orders。
- 空间清理、时钟推进、武器选择与 `CPlayerInfo::SetPlayerState` / 41705。

对一个客户端调用此函数可能影响该端周围环境，不能假设它仅把玩家血量改回正常。线上模式应该让服务器生命状态机掌握死亡、等待、重生和被捕的转移；引擎适配层按明确事务恢复玩家对象、相机、输入与 UI，并约束原单机重启及环境清理分支。复活过程中不得由某条旧任务重新裁决玩家生死或删除共同世界对象。

警察链同样可定位：`CWanted::Update` / 37889、`CWanted::ReportCrimeNow` / 37768、`CDispatchManager::EnableDispatch` / 38191、`CDispatchManager::BlockDispatchResourceCreation` / 38192。需要统一犯罪与响应世界；调度资产配置本身没有网络所有权策略。

## 8. 建议的统一世界设计

统一协议应围绕世界与实体状态，而不是无限增加页面按键事件。建议至少定义以下边界：

| 统一层 | 最小职责 | 原引擎复用方式 |
| --- | --- | --- |
| 公共世界初始化 | 固定地图/资源版本、世界 epoch、时钟/天气、生成模式、玩家生命规则、调试关闭。 | 以完整模式策略接管单机启动与恢复分支。 |
| 对象目录与生命周期 | 稳定 ID、generation、创建/接纳/删除、死亡/重生版本、迟到加入的完整基线。 | 本地 GUID 与稳定 ID 双向映射；复用池槽位时更新代际。 |
| 区域人口与兴趣管理 | 区域生成决定、唯一模拟者、载入/卸载视野范围、活跃 NPC/交通预算。 | 复用 popcycle/scenario/道路与 GTA AI；未授权的客户端不得生成第二套同区域实体。 |
| 对象所有权 | lease、epoch、超时、迁移、断线接管、车辆驾驶/座位抢占。 | 脚本资源归属与服务端 lease 同时维持。 |
| 状态采样与应用 | 类型化快照、变更版本、速度/朝向/关联/任务意图、确认与纠正。 | 使用统一采样器；仅在已确认安全的引擎阶段应用。 |
| 生命、犯罪与交互裁决 | 伤害、击杀、重生、被捕、车辆破坏、拾取和任务占用的统一结果。 | 原 AI/物理作模拟输入；重要结果不得由各端独立宣布。 |

若保留“不在服务端存放游戏资源、运行游戏引擎”的约束，区域 AI/车辆模拟只能由客户端承担或显著简化。服务端可以授权唯一模拟者、验证明显异常并最终发布对象状态，但不能因此声称它已经独立重算了原 GTA 碰撞与路径。这应在整体方案里明确，不能留给之后某个伤害补丁掩盖。

统一世界的一致性约束包括：环境实体数量与身份一致、区域往返保留实体、驾驶与乘员所有权清晰、断线迁移不重复生成、迟到加入取得完整基线，以及死亡/逮捕与重生保留共同世界。

## 9. 复核方式

资源计数通过 `Path('gta5data/data').rglob('*')` 统计实际文件；XML 用标准库 `ElementTree` 读取实际根类型、集合和字段。大 `paths.xml` 仅读取头部，没有加载完整 145 MB 文档。带 `xi:include` 的 meta 在内存副本里补标准 namespace 后解析，原文件未改变。

WASM 证据使用现有 [inspect_native_bridge.py](../tools/inspect_native_bridge.py) 的 `WasmAudit`：

```python
from inspect_native_bridge import WasmAudit, DEFAULT_WASM
audit = WasmAudit(DEFAULT_WASM)
for index in (61943, 57672, 57673, 8689, 50118, 52750, 18883, 41485, 80397):
    print(audit.descriptor(index))
    result = audit.instructions(index)
    print(result['decode_complete'])
    print(result['instructions'])
```

所有本文描述为“完整解码”的函数，指令读取均到达函数体末尾。只列为名称/ABI 线索的函数，没有因此宣称运行时可安全调用。RPF 仅复核魔数、记录数量、名称区长度与加密标识，未把加密字节误认成 script 内容。现有 [角色同步接口审计](角色同步接口审计.md) 和 [原线上模式审计](原线上模式审计.md) 提供了活动脚本/TLS、资源归属和原 peer 传输的补充证据。
